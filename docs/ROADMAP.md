# 路线图

这份路线图优先保持产品思想的一致性，而不是快速堆积功能。

## Seed：可运行的产品假设（当前）

已完成：

- 本地总览、知识图谱、变化流、发现页、实验页和审核页。
- 技术路线、已评估技术和待评估候选使用同一张连通图。
- 按公开规模信号显示相对节点大小。
- 学习笔记的新增、查看、编辑、归档、恢复和关系管理。
- Codex 会话显式导入、回到原任务和带上下文创建新调研任务。
- GitHub/PyPI 变化收集与 GitHub 多查询族广度发现。
- YAML 作为可审查源数据，SQLite 作为可重建索引。

Seed 的验收标准是：新用户能看懂这个项目想验证什么，能在本地启动，能看见对话、笔记、证据、候选和审核之间的边界。

## 0.2：把“对话 → 知识”做扎实

- 完成真实 Codex 会话同步回路，支持增量同步和重复内容检测。
- 将会话提炼为概念、问题、质疑、回答和修正链，避免一次生成大量低价值节点。
- 改进节点详情、关系编辑、全文可读性和图谱聚焦/过滤。
- 为每个学习节点显示会话来源、外部证据、查证状态和上次复盘时间。
- 允许用户从任意节点开启新 Codex 追问，完成后将结果连回原节点。

## 0.3：扩大搜索广度，但保持可审计

- 增加 npm Registry、arXiv API、RSS/Atom 和官方组织新项目监测。
- 建立技术类别覆盖仪表盘，显示语言、生态、能力和来源空白。
- 保存每次发现运行的新增唯一率、重复命中率、不完整结果和排除原因。
- 增加实体去重，识别仓库、包、更名项目和历史 Fork 之间的同一性。
- 只将值得人审核的变化进入信息流，不把每次版本变化变成噪音。

## 0.4：可证伪的调研与实验

- 建立调研问题队列，为每项任务记录目标、证据空白、时间预算、模型和完成标准。
- 为重要结论生成最小对照实验，保存输入、环境、原始日志和结果。
- 在“官方声称”、“源码观察”、“本地实验”、“个人使用结果”和“AI 推断”之间建立明确标签。
- 增加证据过期和重查规则，对快速变化的框架和定价使用更短有效期。
- 为冲突证据提供 `contested` 工作流，不覆盖历史观察。

## 0.5：长周期调研与复盘

- 评估 Codex 与 Prime Agent 类 Harness 在同一调研任务上的完成率、人工干预、额度/成本、恢复能力和证据质量。
- 支持持久目标、中断恢复、可控子 Agent 和按预算停止。
- 从运行轨迹中提炼可复用调研策略，但任何长期记忆更新都必须可查看、可限定范围、可回滚。
- 将错误经验污染、子 Agent 彼此强化错误和无界成本列为一级风险。
- 长期 Agent 只作为研究执行器，不取代 Agent Tech Radar 的证据、版本和审核模型。

## 1.0：可信的个人技术决策记忆

1.0 不以功能数量为标准，而以下列闭环是否稳定为标准：

- 一段重要 Codex 会话可以被准确提炼、增量同步并保留认知来源。
- 系统能持续发现值得看的新技术，同时能说明搜索边界和遗漏可能。
- 重要外部断言能回到一手来源或可重复实验。
- 每次知识升级都有可查看的差异、证据和人工决定。
- 图谱在规模增长后仍然能帮助用户导航，而不是变成一团无法阅读的连线。
- 用户可以从过去的问题、结论和决策中看见自己的认知如何改变。
